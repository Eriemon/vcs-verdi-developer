# VCS/Verdi Non-GUI Capability Matrix

This skill covers a scripted non-GUI subset of VCS and Verdi workflows. It does not claim complete coverage of every official Synopsys VCS/Verdi command option or GUI feature. Status values are `supported`, `remote-evidence-required`, `guarded`, and `unsupported`.

| Capability | Status | Evidence Requirement |
| --- | --- | --- |
| Environment probe for `vlogan`, `vhdlan`, `vcs`, `VCS_BIN`, `verdi`, `fsdbreport`, Verdi NPI Python, licenses, PLI, shell compatibility | supported | targeted `check_env.py` unit tests and local gate |
| SystemVerilog and Verilog compile planning with include dirs, defines, libraries, multiple filelists, tool overrides, environment injection, expected artifacts, and manifest input | supported | manifest schema tests and `smoke_vcs_verdi.py --dry-run --json` tests |
| VHDL compile planning with `vhdlan` ordering before `vlogan` | supported | manifest dry-run tests; real execution is `remote-evidence-required` |
| VCS Makefile/filelist import for ref-style projects, including `VCS`, `VERDI`, `VCS_FLAGS`, `SRCS`, `+incdir`, `-top`, VCD dump flags, and `./simv -l` logs | supported | local gate dry-runs against `ref/3-tinyriscv-modified` and non-UVM `ref/4-sigarch-rtl-project-template` examples |
| Course-style Makefile import with `cd <workdir> && vcs`, `$(shell find $(PWD)/../...)`, line-commented `VCS_OPTIONS += ... ###`, explicit `--make-var TOP=...`, `-R`, FSDB `verdi -ssf`, `./<simv> -l`, `urg -dir`, and compile/sim check scripts | supported local plan | local gate dry-runs against `ref/12-CSCD` plus `ref/13-Computer-Organization` mp_setup, mp_pipeline, mp_cache, and mp_verif examples; real VCS/URG execution is `remote-evidence-required` |
| Edalize/CAPI2-style VCS input import for files, file types, toplevel, plusargs, vlogdefines, vlogparams, `vcs_options`, and `run_options` | supported | targeted `import_edalize_project` unit test plus importer CLI gate coverage |
| cocotb VCS/VPI non-GUI dry-run planning for Verilog/SystemVerilog examples, including `pli.tab`, `+vpi`, `-P`, `+define+COCOTB_SIM=1`, `-load`, `MODULE`, `TOPLEVEL`, and `TOPLEVEL_LANG` | supported local plan | `cocotb_vcs_flow.py` unit tests and local gate dry-runs against the `ref/14-cocotb` adder Makefile; real cocotb/VCS execution is `remote-evidence-required` |
| cocotb VCS VHDL/VHPI execution | unsupported | The cocotb VCS reference path is VPI-only; `cocotb_vcs_flow.py` must return `vcs_cocotb_vhdl_unsupported` when `VHDL_SOURCES` are present |
| PicoRV32/RISCV-DV style VCS filelist import with `cd <dv> && vcs -f cfg/vcs.f`, `+define+`, `-sverilog`, `-cm`, `-cm_dir`, `-timescale`, and explicit `simv` output | supported | local gate dry-run against the `ref/6` pattern; real VCS execution is `remote-evidence-required` |
| RISCV-DV generator, VCS compile, `simv +hex/+trace`, URG, and trace-compare command planning | supported | `riscv_dv_flow.py --dry-run --json` tests; RISCV-DV, RISC-V GCC, Spike, VCS, and URG execution remain `remote-evidence-required` |
| ModelSim Tcl and Icarus Makefile conversion into VCS manifest candidates with source glob diagnostics, `SIMULATION` defines, include dirs, top module, and pre-sim hex artifact checks | supported | `import_vcs_project.py` tests and local gate dry-runs against the `ref/7` pattern; missing RTL, hex, or cross toolchain inputs are blockers, not pass evidence |
| KVIPS APB/AHB/AXI4 VCS planning with `-ntb_opts uvm-1.2`, filelist expansion, UVM plusargs, regression lists, FSDB PLI, `fsdbreport`, and guarded `verdi -ssf -nologo -exit` checks | guarded | `kvips_vcs_flow.py` tests and local gate dry-runs against the `ref/8` pattern; UVM, VCS, and Verdi execution are optional external dependencies and not core low-dependency support |
| FP-Gen Genesis2 to VCS planning with generated filelists, `top_FPGen`, VCS/VPD simulation, SAIF runtime args, and guarded DC/ICC gate-level simulation commands | supported | `fpgen_vcs_flow.py` tests and local gate dry-runs against the `ref/9` pattern; Genesis2, DesignWare/GTech libraries, VCS, DC, ICC, and licenses remain execution blockers until fresh remote evidence exists |
| SystemVerilog DPI shared-library planning through VCS `-sv_lib` and `LD_LIBRARY_PATH` | supported | manifest and CLI dry-run tests using `ref/5-pysv` style inputs; real execution is `remote-evidence-required` |
| UVM compile and simulation flows requiring `UVM_HOME`, `uvm.sv`, or `uvm_dpi.cc` | guarded | Importer marks UVM as an optional external dependency and skips UVM-specific inputs; local gate includes a UVM-optional diagnostic dry-run but does not count UVM as core support |
| VCS elaboration and `simv` simulation with plusargs, seed, timeout, UCLI dump command, logs, and artifacts | remote-evidence-required | dry-run tests plus fresh remote EDA execution evidence |
| FSDB dump presence and nonzero artifact checks | remote-evidence-required | unit tests plus fresh remote EDA host `waves.fsdb` evidence |
| Verdi non-GUI FSDB readback through `fsdbreport` | remote-evidence-required | `fsdb_tools.py` tests plus fresh remote EDA host `report.txt` evidence |
| FSDB NPI-first info/list/read planning with CLI fallback, signal path normalization, banner filtering, and zero-byte rejection | supported | `fsdb_tools.py` unit tests; real NPI execution is `remote-evidence-required` |
| FSDB conversion command planning through `fsdb2vcd`, `vcd2fsdb`, and `vpd2fsdb`, including VCD-first non-GUI Verdi readback plans | supported | command construction tests; real conversion is `remote-evidence-required` |
| VCS coverage planning with `-cm`, stable `-cm_dir`, URG `-full64` auto-detection, command construction, and URG failure diagnosis | supported | local gate CLI probe plus manifest/smoke dry-run coverage planning; real URG report generation remains `remote-evidence-required` |
| URG runtime and loader diagnostics | supported | local gate CLI probe; remote evidence must include wrapper, `vcs -location`, `ldd`, candidate hashes, loader activation order, and optional strace evidence when coverage fails |
| URG coverage variant matrix for wrapper/direct `urg1` and line/cond/tgl/combined reports | supported | local gate CLI probe; real execution remains `remote-evidence-required` |
| URG report generation execution | remote-evidence-required | Fresh remote EDA evidence must show the default `line+cond+tgl` variant generates a nonzero report directory before this row can be claimed as executed |
| UCAPI overlay patch workaround for URG internal failures | guarded | local gate CLI probe plus explicit remote-evidence review; apply only inside validation overlays with `VCS_VERDI_ALLOW_UCAPI_PATCH=1`, require loader-effective runtime evidence, and never patch a shared vendor install path directly |
| Batch regression over multiple manifests with JSON and JUnit-style reporting | supported | local gate CLI probe and script-matrix audit |
| VCS/Verdi log analysis for compile, license, platform, PLI, and FSDB failures | supported | `analyze_logs.py` unit tests |
| Machine-readable evidence bundle collection for smoke, mixed VHDL/SV, coverage/URG matrix, and FSDB conversion | supported | `collect_evidence.py` unit tests; real matrix execution is `remote-evidence-required` |
| Claim/evidence hard gate for factual readiness statements | supported | `evidence_claim_gate.py` unit tests and local quality gate against `assets/evidence/non_gui_claims.json`; factual claims without evidence fail |
| Remote EDA detached validation bundle planning and strict matrix evidence validation | remote-evidence-required | `remote_eda_gate.py` tests; execute minimal smoke, mixed VHDL/SV, coverage/URG, and FSDB conversion on remote EDA host for proprietary-tool confidence |
| Verdi RC layout generation for signal restore scenarios | supported | `generate_rc.py` unit tests against shipped wave templates and review checklist |
| GUI Verdi automation, Tk send, and IPython-driven control | guarded | Not part of the non-GUI confidence target |
| Complete coverage of every official Synopsys option | unsupported | Explicitly out of scope |

Supported rows must have at least one local unit test, dry-run test, or remote execution record. Rows marked `remote-evidence-required` must not be reported as factually executed from a Windows-only local run. Dry-run output, GUI launch, or compile-only success never upgrades `eda_execution_confidence` to `passed`.
